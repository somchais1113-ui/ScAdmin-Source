# SCWork Admin V2.1.35 — Phase 04: Approved Rate Card Publishing

**Status:** Code package and offline QA completed. SQL 004 has **not** been applied to your Supabase Production, and the live customer website **has not** been changed. No demo prices are published.

## Business goal

Build a safe, auditable **Draft → Review → Approve → Publish → Rollback** lane that keeps the Admin Pricing Master private. Publish **only sanitized selling prices** for B2C and B2B; never send source Supplier prices, margins, invoices, Job Profitability, Cost Profiles or customer data to the Public Website.

### What is included

- `admin-deploy/index.html` + `rate-card-publishing.css` + `rate-card-publishing.js` + `rate-card-guard.js`: UI for importing a published-sale-price export, comparing the first-tier price against LIVE, selecting an approved Cost Profile, Owner approval, publication and audited rollback.
- `admin-setup/004_scwork_rate_card_publishing.sql`: **additive** SQL migration after 001 → 002 → 003. All mutations are transactional, MFA+role gated RPCs. The public singleton table holds the sanitized *live* snapshot only.
- `public-update/`: changes to Smart Quote, Label page and read-only client-side loader. A disabled placeholder configuration leaves current customer behavior unchanged until after final acceptance.
- `PHASE04_PRE_FLIGHT_READ_ONLY.sql` and `PHASE04_POST_FLIGHT_READ_ONLY.sql`: review/check commands.
- Tests: 14 Rate Guard tests (including a card generated by the actual Pricing Master), Public Loader success/failure tests, Cost Engine 16 cases, Job Engine 13 cases, and browser desktop/mobile tests.

### Deployment flow — **do not skip the gates**

1. **BACK UP** the GitHub Admin Repo, the existing Public Website and Supabase before any migration. Do not disable or remove MFA/RLS. Review SQL 004 in a staging database with the same 001/002/003 schema first.
2. Run `PHASE04_PRE_FLIGHT_READ_ONLY.sql`. All 001/002/003 components must exist. If Phase 03 is not yet installed, finish its staging and acceptance tests **before** Phase 04.
3. Run `004_scwork_rate_card_publishing.sql` in **STAGING**, then the POST FLIGHT query. Test `anon` (no private data), Owner (AAL2), Editor (AAL2), Viewer (AAL2), and an Owner/Editor session at AAL1. Only when passed apply migration 004 to Production.
4. Upload files under `admin-deploy/` to your **existing** `ScAdmin-Source/admin-deploy/` folder. Do **not** replace `config.js`; no secret/service-role key is present in these files. Vercel root stays `admin-deploy` if that is the current working layout.
5. Upload `public-update/` paths into corresponding locations in your **Full Package/Public Website source**, deploy to test/staging first. `config/public-rate-config.js` has `enabled:false` and blank Supabase URL/key, so default customer behavior remains manual quoting.
6. Owner logs into Admin with MFA, selects the **Approved Cost Profile** and uploads `pricing-public-data.js` exported by the private `tools/pricing-workbench.html` (from localhost). Never upload `SCWORK-PRIVATE-pricing-master.json` or private Supplier export.
7. Owner must review **ALL tiers and add-ons** in Pricing Master (the Admin comparison table is only an overview), note the Cost Profile and Margin audit, then Approve; separately click Publish. The SQL RPC validates the JSON again. No automatic Supplier→Public Price link.
8. Confirm read-only API from an anonymous browser: `/rest/v1/scwork_public_rate_card_live?select=version,card,published_at&id=eq.1` returns exactly one row containing **selling rates only**. Viewers cannot update this table; only Owner/MFA publish RPC can.
9. Only after end-to-end acceptance, enter Supabase Project URL and Publishable Key in `config/public-rate-config.js` (public repo) and change `enabled:true`. Public pages then fetch the single LIVE rate card; if unavailable, they fall back to **manual quote**, not stale prices. Test B2B/B2C separately on the public quotation page.
10. Test rollback from a prior approved/superseded version; it creates a **new** release `RB-...` and preserves the previous history. Test that browser receives the new version after refresh and that no old price is cached by the Public Loader.

### Pricing and financial accuracy controls

- **SCWork is not VAT registered**: Public Sale `vatRate` must be exactly `0`, enforced in client guard and SQL 004. Supplier input VAT that cannot be credited stays in cost calculations.
- **Supplier approval != Cost Profile approval != Selling Rate approval != publication**.
- **Selling prices alone cannot mathematically certify target margin**: because costs are private, the SQL requires a previously approved Cost Profile, an Owner acknowledgement of independent margin review, and a review explanation. Full margin checking across product/quantity/add-ons still requires Pricing Master sign-off. This is deliberately not represented as “automatic server-side profit guarantee.”
- **Legacy price descriptions**: the old private PVC source description contained `190 ฿/ตร.ม.` from demonstration data. V2.1.35 removes that example amount; the new validator rejects stale amounts embedded in public material descriptions so they cannot conflict with approved selling rates.
- **Version snapshots** are immutable in the sense that only server RPCs change status fields; the JSON card in each version is never replaced. Published pointer updates atomically. Rollback creates a new version, not an in-place rewrite.
- **Public API exposure** is limited to `scwork_public_rate_card_live`, which has only card, version, published timestamp. Strict key allowlist rejects private costs and customer fields; no browser can insert/update live row.
- **Cloud fallback**: missing/invalid/network-error LIVE price → **no online estimate**, ask for a manual quote. No cached stale prices.
- **B2B**: The customer page allows switching buyer mode; company selling rates are public if you publish them, not an authenticated confidential contract rate. Keep custom contracted prices in a separate private quotation system.
